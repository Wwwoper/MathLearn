## 1. Общее описание проекта

### 1.1 Цель

Создать веб-приложение для школьников 7–10 лет для изучения и закрепления таблицы умножения.
В основе — научно обоснованный метод **интервального повторения (Spaced Repetition)** и перспективное расширение в виде локального **ИИ-тьютора**, который анализирует прогресс ученика и самостоятельно формирует план следующих уроков.

### 1.2 Целевая аудитория

- **Ученики:** дети 7–10 лет (2–4 класс)
- **Родители:** контроль прогресса через отдельный дашборд
- **Учителя (будущее расширение):** просмотр статистики класса

### 1.3 Первый модуль

Таблица умножения от 1 до 10 включительно — 100 уникальных фактов.

### 1.4 Ключевые принципы

- **Адаптивность** — система сама определяет, что повторять сегодня
- **Геймификация** — streak, XP, ачивки для мотивации детей
- **Локальный ИИ** — анализирует статистику ученика без отправки данных во внешние облачные сервисы

### 3.1 Взаимодействие компонентов

```text
Ученик открывает /learn
    → React запрашивает GET /api/sr/queue
    → FastAPI получает карточки из PostgreSQL
    → SR Engine отбирает записи, где next_review_at <= now()
    → Клиент получает очередь карточек на сегодня

Ученик отвечает на карточку
    → POST /api/sr/review { card_id, rating, response_time_ms }
    → SM-2 пересчитывает ease_factor, interval_days и next_review_at
    → Результат пишется в sr_reviews
    → Обновляются XP, streak и локальная статистика

Ночной фоновый job
    → AI Tutor Service собирает статистику ученика за период
    → Формирует structured prompt
    → Отправляет запрос в Ollama
    → Получает JSON-рекомендации
    → Сохраняет lesson plan в ai_recommendations
```

## 4. Ключевая методика обучения

### 4.1 Выбранная техника

Для первого релиза выбрать метод **Spaced Repetition** как основную технику запоминания таблицы умножения.
Он лучше подходит для долгосрочного удержания, чем простое заучивание подряд, потому что повторение происходит в нужный момент до полного забывания.

### 4.2 Алгоритм SM-2

```text
Входные данные после ответа:
  q = rating (1..4):
  1 = не знал
  2 = трудно
  3 = знал
  4 = легко

Формулы:
  ease_factor_new = ease_factor + (0.1 - (4 - q) * (0.08 + (4 - q) * 0.02))
  ease_factor_new = max(1.3, ease_factor_new)

  if q < 2:
    interval = 1
    repetitions = 0
  elif repetitions == 0:
    interval = 1
  elif repetitions == 1:
    interval = 3
  else:
    interval = round(previous_interval * ease_factor)

  next_review = today + interval days
```

### 4.3 Прогрессивный учебный план

| Неделя | Таблицы | Обоснование |
|---|---|---|
| **1** | ×1, ×2, ×10 | Быстрый вход и уверенность |
| **2** | ×5, ×11, квадраты | Простые паттерны |
| **3** | ×3, ×4, ×9 | Производные и логические связи |
| **4** | ×6, ×7, ×8 | Самые сложные комбинации |

### 5.1 Страницы

### 5.2 Основные компоненты

#### `<FlashCard />`
- Показывает пример: `6 × 7 = ?`
- После действия ученика переворачивается и показывает ответ
- Поддерживает анимацию и состояния `question / answer / submitted`

#### `<SRRatingButtons />`
- 4 оценки сложности ответа
- Цветовая дифференциация по уровню уверенности
- Передаёт rating в backend для перерасчёта интервального расписания

#### `<PythagoreanTable />`
- Таблица 10×10
- Цветовая индикация по уровню владения фактом
- Клик по ячейке открывает мини-детали по истории ответа

#### `<TimerDrill />`
- Поле ввода ответа
- Таймер на вопрос
- Автопереход к следующему примеру

#### `<AIRecommendationCard />`
- Показывает план от локального ИИ
- Содержит объяснение, почему этот урок выбран следующим
- Имеет CTA-кнопку запуска рекомендованного урока

## 7. Модели данных

### 7.1 Основные таблицы

```sql
CREATE TABLE users (
    id UUID PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    xp INTEGER DEFAULT 0,
    level INTEGER DEFAULT 1,
    current_streak INTEGER DEFAULT 0,
    max_streak INTEGER DEFAULT 0,
    created_at TIMESTAMPTZ DEFAULT now(),
    last_active_at TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE sr_cards (
    id UUID PRIMARY KEY,
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    factor_a SMALLINT NOT NULL CHECK (factor_a BETWEEN 1 AND 10),
    factor_b SMALLINT NOT NULL CHECK (factor_b BETWEEN 1 AND 10),
    ease_factor FLOAT DEFAULT 2.5,
    interval_days INTEGER DEFAULT 1,
    next_review_at TIMESTAMPTZ DEFAULT now(),
    last_reviewed_at TIMESTAMPTZ,
    repetitions INTEGER DEFAULT 0,
    lapses INTEGER DEFAULT 0,
    UNIQUE (user_id, factor_a, factor_b)
);

CREATE TABLE sr_reviews (
    id UUID PRIMARY KEY,
    card_id UUID REFERENCES sr_cards(id),
    user_id UUID REFERENCES users(id),
    rating SMALLINT NOT NULL CHECK (rating BETWEEN 1 AND 4),
    response_time_ms INTEGER,
    reviewed_at TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE drill_sessions (
    id UUID PRIMARY KEY,
    user_id UUID REFERENCES users(id),
    started_at TIMESTAMPTZ DEFAULT now(),
    ended_at TIMESTAMPTZ,
    total_questions INTEGER DEFAULT 0,
    correct_answers INTEGER DEFAULT 0,
    avg_response_ms INTEGER
);

CREATE TABLE ai_recommendations (
    id UUID PRIMARY KEY,
    user_id UUID REFERENCES users(id),
    lesson_plan JSONB NOT NULL,
    reasoning TEXT,
    model_name VARCHAR(50),
    generated_at TIMESTAMPTZ DEFAULT now()
);
```

## 9. ИИ-ассистент обучения (AI Tutor)

> **Статус:** будущее расширение приложения. Архитектура должна быть заложена уже в первой версии.

### 9.1 Назначение

Локально запущенная ИИ-модель изучает статистику ученика и предлагает, какие уроки нужно проходить дальше.
Модель должна работать на сервере без передачи персональных данных во внешние API.

### 9.2 Цели AI Tutor

- Анализировать слабые и сильные стороны ученика
- Определять перегрузку или, наоборот, готовность к новой теме
- Предлагать следующий урок, порядок карточек и drill-сессий
- Формировать краткое объяснение для ученика и родителя

### 9.3 Техническая реализация

```text
Компоненты:
- Ollama server
- Локальная модель: Qwen2.5:7b или Llama 3.x 8b
- AI Tutor Service в backend
- Ночной batch-job для генерации рекомендаций
```

### 9.4 Источники данных для ИИ

ИИ должен анализировать:
- среднюю точность за 7, 14 и 30 дней
- среднее время ответа
- факты с наибольшим числом ошибок
- факты с самым низким ease_factor
- регулярность занятий
- streak и пропуски
- какие таблицы уже освоены, а какие нет

### 9.5 Формат результата

ИИ должен возвращать структурированный JSON:

```json
{
  "days": [
    {
      "day": 1,
      "focus_facts": ["7x8", "6x7"],
      "recommended_mode": "learn",
      "target_cards_count": 10,
      "new_table": null,
      "reasoning": "Ученик часто ошибается в примерах на 6 и 7."
    }
  ],
  "general_advice": "Снизить нагрузку и повторить трудные примеры.",
  "motivation_message": "Отличный прогресс, продолжаем в том же темпе."
}
```

### 9.6 Ограничения будущего ИИ-модуля

- ИИ не принимает финальные решения без бизнес-правил backend
- Рекомендации должны проходить JSON-валидацию
- При ошибке модели система должна fallback-иться на стандартный SR-план
- Все рекомендации должны логироваться и храниться в БД

### 9.7 Пример сценария

```text
Если ученик 5 дней подряд ошибается в 7×8 и 6×7,
AI Tutor рекомендует на следующий день:
- короткий урок из 8 карточек
- затем drill только по таблицам ×6 и ×7
- без добавления новой таблицы
- с мотивационным сообщением и сниженной нагрузкой
```

## 11. MVP — порядок реализации

### Этап 1. Инфраструктура
- Настроить `docker-compose.yml`
- Поднять `postgres`, `redis`, `backend`, `frontend`
- Подготовить `.env.example`

### Этап 2. Основа backend
- Реализовать модели БД и миграции
- Сделать регистрацию и авторизацию
- При регистрации создавать 100 карточек таблицы умножения

### Этап 3. Ядро обучения
- Реализовать `SM-2` в `sr_engine.py`
- Поднять `/api/sr/queue`, `/api/sr/review`, `/api/sr/progress`

### Этап 4. Drill-режим
- Реализовать быстрые упражнения на время
- Сохранять результаты сессий
- Добавить простую статистику

### Этап 5. Геймификация
- XP, уровни, streak
- Ачивки
- Главная страница с прогрессом

### Этап 6. Frontend MVP
- Страницы `/learn`, `/drill`, `/table`, `/stats`
- Компоненты карточек и таблицы
- Адаптивный интерфейс для мобильных устройств

### Этап 7. Будущее расширение AI Tutor
- Подключить Ollama в локальном контуре сервера
- Создать `AITutorService`
- Добавить nightly job генерации рекомендаций
- Реализовать экран `/ai-tutor`
